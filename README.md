# JioSaavn for SpotiFLAC

Adds JioSaavn as a search and download source. Saves **320 kbps AAC** with the
cover art and full metadata muxed into the file.

Built against the unofficial [jiosaavn-api](https://github.com/sumitkolhe/jiosaavn-api).

## Install

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

Then in SpotiFLAC: **Settings → Extensions → Import** and pick
`jiosaavn-1.0.0.spotiflac-ext`.

## What it does

**Search** — a JioSaavn tab returning songs, albums, artists and playlists in
one list. Tap an album, playlist or artist to open its track list.

**Links** — paste any `jiosaavn.com` song / album / artist / playlist URL and it
resolves to the right screen.

**Download** — picks the requested bitrate from JioSaavn's five options, falling
back to the next best if the exact one is missing. Then it:

1. downloads the raw AAC stream,
2. downloads the 500×500 cover art,
3. writes an FFmpeg metadata file, and
4. muxes all three into one tagged `.m4a` with `-c copy` (no re-encode, so no
   quality loss).

Tags written: title, artist, album, album artist, date, track, language,
publisher (label), copyright and the source URL as a comment.

`skipMetadataEnrichment` is `true` in the manifest — JioSaavn already returns
complete metadata, so there is no point round-tripping through Deezer/Spotify.

## Settings

| Setting | Default | Notes |
|---|---|---|
| API Base URL | public instance | Point at your own Vercel deploy if the public one gets rate limited |
| Search Results | everything | `songs` is one API call, `everything` is four — drop it if search feels slow |
| Song Results Per Search | 25 | 1–50 |
| Embed Cover Art & Metadata | on | Off = save the raw stream untouched |
| Cover Art Size | 500×500 | |
| Look Up ISRC (Odesli) | off | See below |
| Progress Reporting | fraction | Switch to `percent` if the progress bar never moves |
| Debug Logging | off | |

Two buttons: **Test Connection** and **Clear Cache**.

### The Odesli setting is the interesting one

JioSaavn is AAC-only and returns no ISRC, which normally blocks SpotiFLAC from
falling back to lossless sources. Turn this on and `enrichTrack()` asks
song.link to translate the JioSaavn page into an ISRC plus Tidal / Qobuz /
Deezer IDs. When it finds a Tidal or Qobuz ID, SpotiFLAC downloads **real FLAC
from there instead** — no search, no guessing.

Off by default because it adds one network request per track and changes where
your audio actually comes from.

## Post-processing

One optional hook, **Convert to MP3 320**, off by default. Re-encodes to MP3
while keeping the embedded art and tags. Note this is a lossy→lossy transcode;
only use it for devices that cannot play `.m4a`.

## Development

```
node test/harness.js       # 25 tests against the live API
VERBOSE=1 node test/harness.js
node test/gen-icon.js      # regenerate icon.png
```

The harness stubs the sandbox globals (`http`, `file`, `ffmpeg`, `storage`,
`matching`, `gobackend`) and runs the real `index.js`, so mapping, quality
selection, URL handling, the FFmpeg command strings and the ffmetadata escaping
are all covered without installing anything.

`test/` is not included in the package.

## Notes and limitations

- **No lyrics.** The lyrics route (`/api/songs/:id/lyrics`) returns 404 on the
  public instance and `lyricsId` is null on every song checked, so lyrics are
  left out entirely.
- **AAC, not FLAC.** 320 kbps is JioSaavn's ceiling. The `.m4a` extension is
  applied regardless of what the app suggests, because mislabelling AAC as
  `.flac` breaks players.
- **No ISRC**, so `checkAvailability()` matches by name, artist and duration.
- **Unofficial API.** Nothing here is affiliated with or endorsed by JioSaavn.
  If they change their internals or the free Vercel instance goes down, this
  breaks. Self-hosting the API is the fix.
- **FFmpeg is optional.** If it is missing or refuses every mux variant, the
  extension re-downloads straight to the output path so you still get playable
  audio — just untagged.
- The music is copyrighted. Keep this to personal use.
